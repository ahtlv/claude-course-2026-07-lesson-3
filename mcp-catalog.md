# Каталог MCP-серверов: что поставить себе

Справочник к занятию 3. Пригодится для домашки — нужно выбрать и поставить один сервер
под свою задачу.

> Ссылки и названия пакетов проверены 25 июля 2026. Экосистема MCP меняется быстро: если
> что-то не открывается или пакет переименовали, ищи актуальный адрес в
> [реестре серверов](https://registry.modelcontextprotocol.io) и не мучайся.

---

## Сначала про количество

В каталогах сейчас больше десяти тысяч MCP-серверов. Большинство из них написаны на
выходных и ломаются при первой же попытке использования, так что гнаться за количеством
не нужно.

Два правила, которые стоит держать в голове:

**Ставь только то, чем реально пользуешься.** Ценность MCP в том, что он убирает трение
в работе, которая у тебя уже есть. Он не создаёт новых полезных привычек: если ты не ведёшь
задачи в Notion, MCP к Notion не заставит тебя их вести.

**Три-пять серверов — оптимум.** Каждый подключённый сервер занимает место в контекстном
окне ещё до того, как ты что-то спросил. Помнишь банку с контекстом с прошлого занятия? Вот
это ровно она. Двадцать серверов не сделают агента умнее, а вот памяти ему оставят меньше.

## Как поставить

Большинство серверов ставится одной командой, меняется только название пакета:

```bash
# поставить сервер
claude mcp add <имя> -- npx -y <пакет>

# поставить для всех проектов сразу
claude mcp add --scope user <имя> -- npx -y <пакет>

# если нужен ключ доступа
claude mcp add <имя> -e API_KEY=твой-ключ -- npx -y <пакет>

# посмотреть, что уже стоит
claude mcp list

# удалить
claude mcp remove <имя>
```

**После установки перезапусти Claude Code** — новые инструменты подхватываются только при
старте сессии. Проверить, что всё подключилось, можно командой `/mcp` прямо в диалоге.

⚠️ **Но так ставятся не все.** Часть сервисов раздаёт свой сервер по-другому: одни держат
его у себя в облаке (тогда подключаешься по адресу, ничего не скачивая), другие идут
Python-пакетом или плагином Docker. В таблицах ниже такие помечены отдельно — смотри
колонку «Установка», прежде чем копировать команду.

Впрочем, всё это можно и не запоминать: скажи агенту своими словами, какой сервер хочешь
поставить, и дай ссылку из таблицы. Он сам разберётся со способом. Именно так мы ставили
Playwright.

## Безопасность: четыре правила

1. **Давай минимально необходимый доступ.** Если серверу хватит одной папки — не давай
   доступ ко всему диску. Если сервис умеет выдавать токен с ограниченными правами — бери
   такой.
2. **Проверяй, что агент собирается сделать.** Ошибочно созданные двадцать страниц в
   заметках — поправимо. Удалённые данные из боевой базы — может быть, уже нет.
3. **Формулируй точно.** «Обнови таблицу» — плохо. «Добавь строку с сегодняшней датой и
   значениями X, Y, Z» — хорошо. С внешними сервисами цена расплывчатой формулировки выше,
   чем при работе с файлами: действие уходит наружу.
4. **Не вставляй ключи доступа в промпты.** Ключ указывается один раз при установке
   сервера и хранится в конфигурации.

Ещё одно, про сам выбор серверов: ставь то, у чего понятный автор — сам сервис или крупный
проект с живым репозиторием. Сервер получает доступ к твоим данным, и «нашёл на просторах»
здесь не лучший критерий.

## А если нужного сервера нет?

Тогда его можно написать самому: MCP — открытый протокол, и сервер под него собирается
на Python и упаковывается в Docker. Это уже полноценная разработка, и на курсе мы туда не
идём, но потолка здесь нет.

Если захочется копнуть:
- [Официальная документация MCP](https://modelcontextprotocol.io)
- [Реестр опубликованных серверов](https://registry.modelcontextprotocol.io)

Протокол, кстати, приняли не только в Anthropic, но и в OpenAI с Google — то есть навык
не привязан к одному инструменту.
