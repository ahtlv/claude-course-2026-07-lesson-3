# Промпт 7 — Твоя видимая папка с глобальными настройками (`claude-config`)

> Инструкция одинаковая для Windows, macOS и Linux — агент сам определяет систему и
> подбирает способ (как в занятии 1 с установкой Git, `github-setup.md`).

**Когда:** первым делом на занятии 3, ещё до основной темы MCP — сразу после того как в
`~/.claude/CLAUDE.md` уже что-то есть (промпт 6, занятие 2). Это база, а не факультатив:
пробовали показать на занятии 2 вживую и не успели довести до конца — доводим здесь.
**Что делает:** переносит твой глобальный конфиг Claude Code из скрытой системной папки
(`~/.claude/` на macOS/Linux, `%USERPROFILE%\.claude` на Windows) в обычную видимую папку
`claude-config`, которая ляжет **рядом с твоими проектами** — в ту же рабочую папку
(у нас это `Work`, то есть получится `~/Work/claude-config`). На старом месте останутся
ссылки (симлинки). Claude Code продолжает работать ровно как раньше — просто теперь
удобно самому доливать туда скиллы, правила и всё остальное, не копаясь в скрытых файлах.
**Как использовать:** отправь промпт ниже как есть — про определение системы можно не
думать, это делает сам агент. А вот если агент спросит, где твоя рабочая папка, — ответь
ему полным путём, это нормальный ход, а не сбой.

> Зачем это вообще нужно: `~/.claude/` — служебная папка, Claude Code всегда читает конфиг
> именно оттуда и это место переименовать нельзя. Но раз внутри лежат обычные текстовые
> файлы, их можно физически хранить в другом, видимом месте, а в `~/.claude/` оставить
> только ссылку (симлинк) на оригинал. Агент не заметит разницы, а тебе будет удобно —
> папка на виду, рядом с проектами: зашёл и добавил что-то новое.

```text
Хочу вынести свой глобальный конфиг Claude Code из скрытой системной папки в обычную
видимую папку claude-config, которая должна лежать РЯДОМ С МОИМИ ПРОЕКТАМИ — внутри моей
рабочей папки, а не в домашней папке и не в корне диска.

Работай только по полным (абсолютным) путям и на каждом шаге показывай мне, что именно
получилось.

Сделай так:

1. Определи мою операционную систему.

2. Найди мою рабочую папку — ту, в которой лежат мои проекты. Скорее всего она называется
   Work и лежит в домашней папке (~/Work, на Windows — %USERPROFILE%\Work). Ищи так:
   а) посмотри, где сейчас открыт текущий проект — рабочая папка это, скорее всего,
      папка на один уровень выше него;
   б) если не сходится — поищи в домашней папке каталог с подходящим именем: Work, work,
      Projects, Dev.
   Нашёл ровно одну подходящую — назови мне её полный путь и продолжай.
   Не нашёл, или кандидатов несколько, или сомневаешься — ОСТАНОВИСЬ и спроси меня, где
   моя рабочая папка. Путь сам не выдумывай и папку наугад не создавай.

3. Проверь, не создавалась ли папка claude-config раньше где-то ещё — в домашней папке,
   внутри текущего проекта или в корне диска. Если нашлась не в рабочей папке — перенеси
   её целиком в рабочую папку, а потом обязательно перепроверь ссылки в системной папке
   конфига и перезапиши те, что указывают на старое место (ссылка на исчезнувшую папку
   ломается молча).

4. Если папки claude-config в рабочей папке всё ещё нет — создай её там.

5. Найди системную папку конфига Claude Code (~/.claude на macOS/Linux,
   %USERPROFILE%\.claude на Windows) и разберись с ФАЙЛАМИ CLAUDE.md, settings.json,
   .mcp.json: если файл существует и ЕЩЁ НЕ является символической ссылкой (symlink) —
   перенеси его в claude-config под тем же именем, а на старом месте создай символическую
   ссылку на новое расположение. Если такого файла нет — просто пропусти, пустышки не
   создавай.

6. Отдельно разберись с ПАПКАМИ rules, skills, commands, agents. Здесь правило другое —
   они нужны мне в любом случае, чтобы я мог сам складывать туда свои файлы:
   - если папки нет ни в системной папке конфига, ни в claude-config — создай её пустой
     внутри claude-config;
   - если папка есть в системной папке конфига и это не символическая ссылка — перенеси
     её в claude-config вместе с содержимым;
   - в системной папке конфига на месте каждой из этих папок в итоге должна стоять
     символическая ссылка на соответствующую папку внутри claude-config;
   - внутри каждой папки, которую ты создал пустой, положи пустой файл .gitkeep — иначе
     пустая папка не попадёт в репозиторий на следующем шаге (промпт 8).

7. На macOS и Linux используй `ln -s`. На Windows создание симлинков требует включённого
   Режима разработчика или запуска от имени администратора. Если упрёшься в ошибку
   доступа — не пытайся обойти её скрытыми способами, а объясни мне простыми словами, что
   происходит, и скажи включить Режим разработчика так: нажать Win+R, вставить
   ms-settings:developers, нажать Enter и включить переключатель «Режим разработчика», а
   потом перезапустить VS Code. Проверь мою версию Windows и, если знаешь точный путь
   через меню Параметров именно для неё, назови и его тоже.

8. Ничего не удаляй безвозвратно — если сомневаешься, лучше скопируй, а не двигай.

9. В конце покажи результат:
   - полный путь к папке claude-config и список того, что внутри неё;
   - список системной папки конфига с указанием, куда ведёт каждая ссылка;
   - отдельно подтверди, что ни одна ссылка не «висит» — то есть каждая указывает на
     реально существующий файл или папку.
```

**Дальше на занятии** — наставник показывает свой `~/Work/claude-config` (живой пример со
скиллами и rules) — у тебя после этого промпта ровно та же картина по тому же пути — и
объясняет то же самое на пальцах: физически файлы лежат в видимой папке рядом с
проектами, а системная папка конфига держит только ссылки на них.

> Папки `rules/`, `skills/`, `commands/`, `agents/` промпт создаёт заранее — даже если
> они пустые. Это сделано специально: дальше по курсу ты будешь класть туда файлы своими
> руками, и место для них уже должно быть готово.

> Следующий шаг, промпт 8 (`08-claude-config-to-github.md`), заводит под эту папку
> приватный репозиторий на GitHub — делай его сразу следом, тоже в начале занятия.

> Следом идёт промпт 10 (`10-rules-nonconformism.md`) — он кладёт в эту папку твоё первое
> правило и учит агента спорить с тобой, а не поддакивать. Делается на том же занятии,
> пока качается браузер.

## Если агент не справился — симлинк руками

Агент справляется почти всегда, но на Windows изредка не хватает прав даже после Режима
разработчика (корпоративный ноутбук, групповые политики). Тогда — вручную.

> В примерах ниже рабочая папка — `Work`. Если твоя называется иначе, подставь своё имя.

<details>
<summary><b>🪟 Windows</b></summary>

В PowerShell, для каждого файла/папки отдельно (пример на `CLAUDE.md` и на папке `rules`
— с файлами и папками синтаксис отличается):

```powershell
New-Item -ItemType SymbolicLink -Path "$env:USERPROFILE\.claude\CLAUDE.md" -Target "$env:USERPROFILE\Work\claude-config\CLAUDE.md"
New-Item -ItemType SymbolicLink -Path "$env:USERPROFILE\.claude\rules" -Target "$env:USERPROFILE\Work\claude-config\rules"
```

Если папки `rules` (или `skills`, `commands`, `agents`) ещё нет — сначала создай её:

```powershell
New-Item -ItemType Directory -Path "$env:USERPROFILE\Work\claude-config\rules"
```

**Ошибка про права?** Нужен **Режим разработчика** — без него Windows не даёт обычному
пользователю создавать символические ссылки.

Как включить (одинаково в Windows 10 и 11): нажми **Win+R**, вставь `ms-settings:developers`,
Enter — откроется нужная страница Параметров. Включи переключатель **«Режим разработчика»**
и подтверди.

> Через меню путь у всех разный, поэтому и дана прямая ссылка: в Windows 11 это
> Параметры → **Система** → Для разработчиков, в ранних сборках Windows 11 —
> Конфиденциальность и защита → Для разработчиков, в Windows 10 — Обновление и
> безопасность → Для разработчиков. Если `ms-settings:` не сработал, открой Параметры и
> набери в поиске «Для разработчиков».

⚠️ **После включения перезапусти VS Code и терминал** (иногда нужен и перезаход в систему):
права выдаются процессу при запуске, поэтому уже открытое окно про них не узнает.

Не помогло — запусти PowerShell от имени администратора (правой кнопкой → «Запуск от имени
администратора») и повтори команды.

Альтернатива через классическую командную строку (`cmd`, тоже может требовать админ-права):

```cmd
mklink "%USERPROFILE%\.claude\CLAUDE.md" "%USERPROFILE%\Work\claude-config\CLAUDE.md"
mklink /D "%USERPROFILE%\.claude\rules" "%USERPROFILE%\Work\claude-config\rules"
```

Обрати внимание: для файла — `mklink`, для папки — `mklink /D`.

</details>

<details>
<summary><b>🍎 macOS / 🐧 Linux</b></summary>

```bash
mkdir -p ~/Work/claude-config/rules
ln -s ~/Work/claude-config/CLAUDE.md ~/.claude/CLAUDE.md
ln -s ~/Work/claude-config/rules ~/.claude/rules
```

Повтори для остальных файлов/папок (`settings.json`, `.mcp.json`, `skills`, `commands`,
`agents`) — принцип тот же: `ln -s <куда переехал файл> <где он был>`. Папки, которых
раньше не было, сначала создай через `mkdir -p`.

⚠️ Если `~/.claude/rules` (или другой путь) уже существует как папка/файл, а не симлинк —
`ln -s` откажется его заменить. Сначала перенеси содержимое в `~/Work/claude-config`
вручную, удали пустой оригинал, и только потом создавай ссылку.

Проверить, что всё встало правильно (ссылки видно по стрелке `->`):

```bash
ls -la ~/.claude
```

</details>
