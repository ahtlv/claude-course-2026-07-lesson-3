# Промпт 7 — Твоя видимая папка с глобальными настройками (`~/claude-config`)

> Инструкция одинаковая для Windows, macOS и Linux — агент сам определяет систему и
> подбирает способ (как в занятии 1 с установкой Git, `github-setup.md`).

**Когда:** первым делом на занятии 3, ещё до основной темы MCP — сразу после того как в
`~/.claude/CLAUDE.md` уже что-то есть (промпт 6, занятие 2). Это база, а не факультатив:
пробовали показать на занятии 2 вживую и не успели довести до конца — доводим здесь.
**Что делает:** переносит твой глобальный конфиг Claude Code из скрытой системной папки
(`~/.claude/` на macOS/Linux, `%USERPROFILE%\.claude` на Windows) в обычную видимую папку
`~/claude-config/`, а на старом месте оставляет ссылки (симлинки). Claude Code продолжает
работать ровно как раньше — просто теперь удобно самому доливать туда скиллы, правила и
всё остальное, не копаясь в скрытых файлах.
**Как использовать:** отправь промпт ниже как есть — про определение системы можно не
думать, это делает сам агент.

> Зачем это вообще нужно: `~/.claude/` — служебная папка, Claude Code всегда читает конфиг
> именно оттуда и это место переименовать нельзя. Но раз внутри лежат обычные текстовые
> файлы, их можно физически хранить в другом, видимом месте, а в `~/.claude/` оставить
> только ссылку (симлинк) на оригинал. Агент не заметит разницы, а тебе будет удобно —
> папка на виду, в неё можно просто зайти и добавить что-то новое.

```text
Хочу вынести свой глобальный конфиг Claude Code из скрытой системной папки в обычную
видимую папку ~/claude-config, чтобы было удобно самому туда добавлять скиллы, правила и
всё остальное.

Сделай так:
1. Определи мою операционную систему.
2. Создай папку ~/claude-config (на Windows — %USERPROFILE%\claude-config), если её ещё
   нет.
3. Найди системную папку конфига Claude Code (~/.claude на macOS/Linux,
   %USERPROFILE%\.claude на Windows). Для каждого из файлов/папок CLAUDE.md,
   settings.json, rules, skills, commands, .mcp.json внутри неё — если он существует и
   ЕЩЁ НЕ является символической ссылкой (symlink), перенеси его в ~/claude-config под
   тем же именем, а на старом месте создай символическую ссылку, указывающую на новое
   расположение.
4. На macOS и Linux используй `ln -s`. На Windows создание симлинков требует включённого
   Режима разработчика или запуска от имени администратора. Если упрёшься в ошибку
   доступа — не пытайся обойти её скрытыми способами, а объясни мне простыми словами, что
   происходит, и скажи включить Режим разработчика так: нажать Win+R, вставить
   ms-settings:developers, нажать Enter и включить переключатель «Режим разработчика», а
   потом перезапустить VS Code. Проверь мою версию Windows и, если знаешь точный путь
   через меню Параметров именно для неё, назови и его тоже.
5. Если чего-то из списка не существует — просто пропусти, ничего не выдумывай и не
   создавай пустышки.
6. Ничего не удаляй безвозвратно — если сомневаешься, лучше скопируй, а не двигай.
7. В конце покажи результат (список файлов в системной папке конфига и куда указывают
   ссылки), чтобы я видел, что получилось.
```

**Дальше на занятии** — наставник показывает свой `~/Work/claude-config` (уже готовый
живой пример со скиллами и rules; у преподавателя папка лежит на уровень глубже, в `Work/`
— принципиально не важно, где именно, важна сама идея) и объясняет то же самое на
пальцах: физически файлы в видимой папке, системная папка конфига держит только ссылки на
них.

> Следующий шаг, промпт 8 (`08-claude-config-to-github.md`), заводит под эту папку
> приватный репозиторий на GitHub — делай его сразу следом, тоже в начале занятия.

> Следом идёт промпт 10 (`10-rules-nonconformism.md`) — он кладёт в эту папку твоё первое
> правило и учит агента спорить с тобой, а не поддакивать. Делается на том же занятии,
> пока качается браузер.

## Если агент не справился — симлинк руками

Агент справляется почти всегда, но на Windows изредка не хватает прав даже после Режима
разработчика (корпоративный ноутбук, групповые политики). Тогда — вручную.

<details>
<summary><b>🪟 Windows</b></summary>

В PowerShell, для каждого файла/папки отдельно (пример на `CLAUDE.md` и на папке `rules`
— с файлами и папками синтаксис отличается):

```powershell
New-Item -ItemType SymbolicLink -Path "$env:USERPROFILE\.claude\CLAUDE.md" -Target "$env:USERPROFILE\claude-config\CLAUDE.md"
New-Item -ItemType SymbolicLink -Path "$env:USERPROFILE\.claude\rules" -Target "$env:USERPROFILE\claude-config\rules"
```

**Ошибка про права?** Нужен **Режим разработчика** — без него Windows не даёт обычному
пользователю создавать символические ссылки.

Как включить (одинаково в Windows 10 и 11): нажми **Win+R**, вставь `ms-settings:developers`,
Enter — откроется нужная страница Параметров. Включи переключатель **«Режим разработчика»**
и подтверди.

> Через меню путь у всех разный, поэтому и дана прямая ссылка: в Windows 11 это
> Параметры → **Система** → Для разработчиков, в ранних сборках Windows 11 —
> Конфиденциальность и защита → Для разработчиков, в Windows 10 — Обновление и
> безопасность → Для разработчиков. Если `ms-settings:` не сработал, открой Параметры и
> набери в поиске «Для разработчиков».

⚠️ **После включения перезапусти VS Code и терминал** (иногда нужен и перезаход в систему):
права выдаются процессу при запуске, поэтому уже открытое окно про них не узнает.

Не помогло — запусти PowerShell от имени администратора (правой кнопкой → «Запуск от имени
администратора») и повтори команды.

Альтернатива через классическую командную строку (`cmd`, тоже может требовать админ-права):

```cmd
mklink "%USERPROFILE%\.claude\CLAUDE.md" "%USERPROFILE%\claude-config\CLAUDE.md"
mklink /D "%USERPROFILE%\.claude\rules" "%USERPROFILE%\claude-config\rules"
```

Обрати внимание: для файла — `mklink`, для папки — `mklink /D`.

</details>

<details>
<summary><b>🍎 macOS / 🐧 Linux</b></summary>

```bash
ln -s ~/claude-config/CLAUDE.md ~/.claude/CLAUDE.md
ln -s ~/claude-config/rules ~/.claude/rules
```

Повтори для остальных файлов/папок (`settings.json`, `skills`, `commands`, `.mcp.json`) —
принцип тот же: `ln -s <куда переехал файл> <где он был>`.

⚠️ Если `~/.claude/rules` (или другой путь) уже существует как папка/файл, а не симлинк —
`ln -s` откажется его заменить. Сначала перенеси содержимое в `~/claude-config` вручную,
удали пустой оригинал, и только потом создавай ссылку.

</details>
